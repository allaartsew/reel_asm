# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Локальная сборка ролика по монтажному листу: `assemble.py` (чистый stdlib + ffmpeg через
subprocess), обёртка `run.ps1`. Сторонних зависимостей нет и добавлять их не нужно.
Проект и вся документация — на русском, комментарии в коде тоже.

## Запуск

```powershell
.\run.ps1 "путь\к\проекту" -DryRun     # план: что нашлось, длительности, расхождения
.\run.ps1 "путь\к\проекту"             # сборка → финал\ролик.mp4
.\run.ps1 "путь\к\проекту" -Output "D:\готово.mp4"
```

**Всегда начинай с `-DryRun`.** Он показывает, где монтажный лист разошёлся с реальными
файлами, и ничего не собирает.

**Сборка молча перезаписывает `финал\ролик.mp4`.** Перед пересборкой отложи прежний рендер
с говорящим суффиксом (`ролик_прошлый-финал.mp4`) — сравнить потом будет не с чем.

Проекты роликов живут внутри `пример\` — там и учебные заглушки (`Проект — утро`),
и боевые ролики (`медовик`, `Проект — мини-сказка`). Новые проекты класть туда же.

## Монтажный лист

Ищется как `монтаж.md` в корне проекта или в `сценарий\`. Формат — в `README.md`,
живые примеры — в `пример\медовик\сценарий\монтаж.md` и `пример\Проект — мини-сказка\`.

- `5 с 2.5` в колонке длительности = взять 5 секунд начиная с 2,5-й секунды фрагмента.
  Это основной инструмент: генерации приходят по 5–15 секунд, а в монтаж идёт лучшее окно,
  и оно почти никогда не с начала.
- Фрагменты ищутся в корне проекта и в `видео\`; звук — в корне, `музыка\`, `озвучка\`, `финал\`.
- `\n` прямо в ячейке текста = перенос строки на экране. Длиннее 44 символов в строке —
  скрипт предупредит, текст уедет за кадр.
- Одна генерация может дать два кадра — две строки на один файл с разными окнами.

## Грабли

- **Формат ролика должен совпадать с форматом генераций.** Кадр приводится через
  scale + центральный crop: 16:9-исходник в вертикали теряет две трети ширины и срезает героя.
- **Строки `- **Музыка:**` / `- **Озвучка:**` ищутся по всему файлу**, включая пояснения
  и бэктики. Написать такую строку «для примера» нельзя — она сразу рабочая.
- Монтажный лист читается как `utf-8-sig`: Блокнот и `Out-File -Encoding utf8` дописывают
  BOM, из-за него шапка таблицы перестаёт распознаваться.
- Файл текста для drawtext пишется с `newline="\n"`: на Windows CRLF даёт лишнюю пустую
  строку и удвоенный межстрочный шаг.
- `_clean` снимает markdown-выделение только по краям ячейки — вырезать `_` целиком нельзя,
  имена генераций сплошь с подчёркиваниями (`Girl_crossing_sea_in_boat.mp4`).
- Кегль = ширина × 46/1080. 64/1080 уже слишком крупно.

## Озвучка

Дорожку рендерит `сценарий\рендер_озвучки.py` внутри проекта: импортирует `Synth`
из `D:\Projects\audio_books` и запускается **её** venv и её моделями.

```powershell
cd D:\Projects\audio_books
.venv\Scripts\python.exe "D:\Projects\reel_assembler\пример\Проект — мини-сказка\сценарий\рендер_озвучки.py"
```

Голос `owl` (сказочная подача) читает медленно: 9 слов ≈ 4,5 сек. Слоты в `LINES`
подгоняются под голос и обязаны совпадать с длительностями в монтажном листе.

## Правки в assemble.py

- Только stdlib и ffmpeg. Никаких пакетов.
- Ошибки — через `MontageError`, текстом, который поймёт человек без терминала.
- Русские имена файлов, папок и колонок — часть контракта, не переименовывать.

## Команды

`/assemble` — пересобрать ролик, `/frame` — подобрать окно `N с M` в генерации,
`/voice` — перерендерить озвучку, `/new-reel` — скелет нового проекта.
